# Zero-token Kind end-to-end test

This opt-in test proves the Kubernetes deployment path generated by
`otel-generate-config`.

The test generates an application overlay, deploys a small
emitter that consumes the generated OTLP environment variables, and proves that
a unique trace and metric reach the Collector's local `debug` exporter. The
application connection contract is SHA-bound to the generated production
`kubernetes/collector.yaml` and passes the coordinated validator before the
local test profile is deployed.

The test always creates a new disposable Kind cluster with a temporary
kubeconfig. Existing-cluster reuse is intentionally refused. The test never
uses the current kubectl context, never creates a Kubernetes Secret, and never
deploys a Collector configuration containing a Splunk Cloud endpoint. Test-only
patches make the live deployment path use a local-debug exporter while leaving
the generated production config validated but unapplied.

Run from anywhere in the repository:

```bash
make test-otel-generate-config-kind
```

Requirements: Bash, Docker, Kind, kubectl, Python 3, `rg`, and network access
to download container images.
Optional environment variables:

- `OTEL_E2E_COLLECTOR_VERSION` (default `0.157.0`)
- `OTEL_E2E_KIND_NODE_IMAGE` (default `kindest/node:v1.31.0`)
- `OTEL_E2E_TIMEOUT` (default `300s`)

Setting `OTEL_E2E_KIND_CLUSTER` is rejected before any cluster operation.
Before creating a cluster, namespace, or manifest-owned resource, the test
checks for collisions and refuses to replace existing state. Cleanup tracks
only resources whose creation succeeded, and Secret queries fail the test if
Kubernetes cannot prove that the test namespaces contain no Secrets. The exit
trap removes applied YAML, namespaces, the disposable Kind cluster, and
temporary files even after a failure. The test also refuses to run when a
Splunk or OTLP-header credential environment variable is present; it checks
variable names without reading their values.
